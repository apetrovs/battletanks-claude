# Журнал прогресса

## 2026-11-05 — Этап 1 (MVP-прототип): завершён, ожидает подтверждения перехода к этапу 2

### Окружение

- Разработка идёт на macOS arm64, а не на Linux, как предполагало исходное задание. Команды `godot` те же.
- Godot в системе отсутствовал; установлена версия 4.7.2 stable через `brew install --cask godot` с одобрения пользователя.
- Песочница блокирует запись в пользовательскую директорию (`~/Library`), поэтому в логах появляются безвредные ошибки про `user://`.

### Принятые решения

- Собственная кинематика на сетке 8 px вместо физического движка: детерминизм и тестируемость. Танки выравниваются по сетке при повороте на 90°.
- Вся симуляция идёт через `Game.step(delta)` с фиксированным шагом 60 Hz.
- Графика рисуется процедурно (`_draw`), без файлов-ассетов; звука нет (этап 3).
- Намерения (`move_intent`, `fire_intent`) задаются подклассами `Tank`; типы танков — ресурсы `TankStats`.
- Уровни — текстовые файлы, разбираемые `LevelData` (без зависимости от сцен); `.txt` нужно добавить в фильтр экспорта Android (этап 4).
- Рендерер `gl_compatibility`, viewport 400x224, окно 1200x672, stretch `canvas_items`/`keep`.

### Организационная заметка

По указанию пользователя в ходе этапа 1 код тестов и документация написаны субагентами Sonnet 5.5 под контролем Opus 5.5 (отступление от п.14/16.3 исходного задания).

Не выполнено:
- Ручная игра с клавиатуры: агент не может нажимать клавиши в окне игры. Управление покрыто тестами через `move_intent`/`fire_intent`, привязки клавиш — через `project.godot`. Нужна ручная проверка разработчиком (`godot --path .`).
- Linux: окружения нет, проверки выполнены на macOS.

### Известные ограничения

- Звука нет (этап 3); графика процедурная.
- Один уровень и один тип врага (этапы 2–3).
- Пуля игрока может разрушить собственную базу (как в жанровом каноне).
- Полоса разрушения кирпича задевает 2 клетки при выравнивании по сетке и 3 клетки без выравнивания.
